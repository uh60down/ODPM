# Snapshot 014: Ontology-Driven Practice Model

## Status

**Epistemic status:** Current positioning, acronym retained
**Snapshot date:** July 2026
**Origin:** Reframing after the method, templates, maturity model, worked examples, and project ontology made ODPM broader than product or project management alone.

> A snapshot records our current best understanding.
> It is dated, revisable, and expected to be superseded.

---

## Summary

The question is no longer: *Is ODPM pure ontology?*

No. ODPM is not pure ontology.

The question is also no longer: *Is ODPM only for product or project management?*

No. ODPM began there, but the framework now applies wherever teams turn intent into verified reality.

The better question is:

> What is ODPM right now?

Current answer:

> **ODPM is the Ontology-Driven Practice Model.**

More fully:

> ODPM is the base ontology-driven framework for turning intent into shared ontology, using that ontology to reach Decision Readiness, executing lightly against it, and updating it as reality pushes back.

---

## What Forced This Snapshot

[Snapshot 013](013-what-is-a-project.md) made the deeper position explicit:

> What ODPM builds is not a methodology. It is the ontology that methodologies are strategies over.

Once that was named, "Project Management" became the wrong genus for the framework.

ODPM was no longer best described as another way to manage projects. It was a practice model beneath product, project, change, delivery, and other execution strategies.

That tension forced this question:

> If ODPM is not a project-management methodology, what does ODPM now stand for?

This snapshot records the current answer: Ontology-Driven Practice Model.

---

## The Two Layers

ODPM has two layers.

### 1. Base Ontology Layer

The Base Ontology Layer answers:

> What is ontology, and how do we model the world?

It introduces the five building blocks:

- Entities
- Relationships
- Actions
- States
- Rules

Earlier snapshots used **Concept** for the first building block. Current ODPM uses **Entity**; see [Entity as the First Building Block](015-entity-as-first-building-block.md).

This layer is domain-independent. It can be used for product work, project delivery, change, operations, AI workflows, organizational alignment, or any other domain where a team must act from a shared model of reality.

### 2. Lightweight Execution Layer

The Lightweight Execution Layer answers:

> How do we use the ontology in real work?

It gives the minimal practice:

```text
source artifact
→ extract ontology
→ mark open questions
→ Chase Understanding
→ decide readiness
→ execute
→ update ontology from feedback
```

This layer is intentionally light. It is not a replacement for PMBOK, Agile, Scrum, Kanban, SAFe, Jira, GitHub, or any other execution method or tool.

Those methodologies manage execution.

ODPM clarifies the shared model of reality those methodologies execute against.

---

## What This Reframes

ODPM has often described itself as sitting upstream of execution.

That remains true, but it is not complete.

ODPM also provides a lightweight way to carry the ontology into execution and update it when reality pushes back. That is why the current model needs both layers:

- **Alignment** — the team shares the same model of reality before acting.
- **Execution** — the team uses the model lightly during work, then updates it from feedback.

Ontology is the base.

Execution is the test.

Feedback is how the ontology evolves.

---

## What This Renames, And What It Does Not

This snapshot does not change the acronym ODPM.

"Ontology-Driven Project Management" is historically accurate but increasingly narrow. As ODPM matured beyond product and project management, the same acronym became better understood as:

> Ontology-Driven Practice Model

This is a Term Migration. Snapshot 012 argues that term migrations should be evidence-driven. The evidence here is the method, templates, maturity model, worked examples, project ontology, and the two-layer structure that now make ODPM broader than project management alone.

The repository can remain ODPM. The expansion changes from a historical domain to the current model.
